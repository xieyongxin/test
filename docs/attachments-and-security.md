# 附件、证据与敏感信息

## 存放与登记

- 原始需求、Word、Excel、PDF 等放入对应批次 `attachments/`；执行截图、日志和输出放入 `evidence/`。
- 在各目录 README 登记文件或稳定外部链接、来源、用途、版本、登记人及脱敏情况；正文使用相对链接引用本地文件。
- 文件名建议使用 `YYYY-MM-DD-主题-版本.ext`；执行证据带 RUN 编号。同名新版本使用新文件名，不覆盖历史证据。
- 附件文件名尽量使用小写英文、数字及连字符；原名有追溯价值时保留原名并在索引说明。不要依赖个人电脑绝对路径。
- 未生成证据时写“待补充”，不要建立不存在的图片或文件链接。空目录通过 README 保留。

## 现有文件导入

1. 确认所属项目、批次、来源、日期和版本；无法确认的信息标为待确认。
2. 检查并脱敏文件内容、截图、批注、隐藏表、修订记录及元数据中的敏感信息。
3. 复制允许入库的文件并登记。来源尚未允许入库时，只登记允许公开的摘要和受控获取渠道。
4. 确定正式维护位置：默认原文件作为来源快照，Markdown 为后续维护正文。尚未完成迁移时可将附件明确标为当前正式版本，Markdown 仅做导航。
5. 从附件提炼内容时注明文件、版本、章节/页码/工作表和可定位单元格；迁移核对完成后登记正式版本切换，停止双份维护。

历史文件中的执行声称不自动构成本批次有效结果。原始记录缺证据时标注待确认，保留其来源，不补造时间、人员或结果。

## 敏感信息

不得入库：密码、访问令牌、API 密钥、Cookie、会话信息、私钥、生产个人信息及未脱敏日志。测试数据使用合成值或脱敏值。环境文档只写访问方式、用途、权限申请和凭据获取渠道。

忽略规则只能防止部分误提交，不能代替内容检查。实际需要入库的证据日志允许保存，因此不全局忽略所有 `.log` 文件。大文件、视频或不适合入 Git 的受控资料保留在团队认可的存储中，登记稳定地址、版本和访问申请方式，不保存带临时凭据的链接。

发现敏感信息已入库时，立即停止传播，通知相关负责人处理失效/轮换和历史清理；仅删除当前文件不能消除 Git 历史中的内容。Agent 不擅自重写历史。
